# Right Sidebar (Page TOC) Implementation

This document describes the custom right sidebar that displays a table of contents extracted from page headings.

## Overview

The right sidebar provides an in-page table of contents for documentation pages, showing h2-h4 headings as clickable links. It appears on the right side of the content area on desktop screens (≥66.5rem).

## Files

### 1. `_includes/components/right_sidebar.html`
Main component that:
- Parses `page.content` for `<h2>`–`<h4>` elements with `id` attributes
- Extracts heading text and IDs
- Renders a nested list with proper indentation
- Only renders if `page.has_toc != false` and headings exist

### 2. `_layouts/default.html` (site override)
Wraps main content and right sidebar in a flex container:
```html
<div class="main-content-with-sidebar">
  <div id="main-content" class="main-content">…</div>
  {% include components/right_sidebar.html %}
</div>
```

### 3. `_sass/custom/custom.scss`
Styles for desktop layout:
- `.main-content-with-sidebar` — flex container with gap
- `.right-sidebar` — fixed 16rem width, sticky positioning, scrollable
- `.right-sidebar-inner` — sticky content within sidebar
- Only active at `@media (min-width: 66.5rem)`

### 4. `_includes/components/sidebar.html` (site override)
Removed the previous left-sidebar TOC inclusion to avoid duplication.

## Usage

Add to any page's front matter:
```yaml
has_toc: true
```

To disable on a specific page:
```yaml
has_toc: false
```

The component automatically picks up all h2-h4 headings that have IDs (generated by the theme's `anchor_headings` include).

## Behavior

- **Desktop (≥66.5rem)**: Right sidebar visible, sticky, scrollable
- **Tablet/Mobile (<66.5rem)**: Hidden (content uses full width)
- **No headings**: Sidebar doesn't render
- **Children nav** (subpages): Still renders in main content area below page content
